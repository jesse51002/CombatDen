# CombatDen API

A Go-based REST API built with Gin framework, following domain-driven architecture principles.

## Tech Stack

- **Framework**: Gin
- **Database**: PostgreSQL with sqlc for type-safe queries
- **Authentication**: Supabase
- **Configuration**: Environment variables with godotenv

## Project Structure

```
.
├── cmd/
│   └── api/
│       └── main.go              # Application entry point
├── internal/
│   ├── config/                  # Configuration management
│   ├── database/
│   │   └── migrations/          # Database migrations (schema)
│   ├── domain/                  # Business domains (self-contained)
│   │   ├── health/              # Health check domain
│   │   │   └── handler.go
│   │   └── user/                # User domain (example)
│   │       ├── handler.go       # HTTP handlers
│   │       ├── service.go       # Business logic
│   │       ├── repository.go    # Data access (imports ./sql)
│   │       ├── dto.go           # Request/Response models
│   │       ├── errors.go        # Domain-specific errors
│   │       └── sql/             # SQL queries and generated code
│   │           ├── queries.sql  # SQL queries (YOU write)
│   │           ├── db.go        # Generated by sqlc
│   │           ├── models.go    # Generated by sqlc
│   │           └── queries.sql.go # Generated by sqlc
│   ├── middleware/              # HTTP middleware
│   └── router/                  # Route registration
├── pkg/
│   └── logger/                  # Logging utilities
├── Makefile                     # Development commands
├── sqlc.yaml                    # sqlc configuration
└── .golangci.yml                # Linter configuration
```

**Key Design Principle:** Each domain is self-contained with all related code (handlers, services, repositories, DTOs) and SQL queries in a `sql/` subdirectory with generated code.

## Getting Started

### Prerequisites

- Go 1.21 or higher
- PostgreSQL 14 or higher
- sqlc (install via `make install-tools`)

### Installation

1. Clone the repository
2. Copy `.env.example` to `.env` and fill in your configuration:
   ```bash
   cp .env.example .env
   ```

3. Install development tools:
   ```bash
   make install-tools
   ```

4. Generate sqlc code:
   ```bash
   make sqlc
   ```

5. Run the application:
   ```bash
   make run
   ```

The API will be available at `http://localhost:8080`

## Development

### Adding a New Domain

Each domain is self-contained with all its code in one directory. Here's how to add a new domain:

1. **Create domain directory:**
   ```bash
   mkdir -p internal/post
   ```

2. **Create SQL subdirectory and queries file:**
   ```bash
   mkdir -p internal/post/sql
   ```
   Create `internal/post/sql/queries.sql`:
   ```sql
   -- name: GetPost :one
   SELECT * FROM posts WHERE id = $1;

   -- name: ListPosts :many
   SELECT * FROM posts ORDER BY created_at DESC;
   ```

3. **Add domain to sqlc.yaml:**
   ```yaml
   - engine: "postgresql"
     queries: "internal/post/sql"
     schema: "internal/database/migrations"
     gen:
       go:
         package: "sql"
         out: "internal/post/sql"
         sql_package: "pgx/v5"
         emit_json_tags: true
         emit_interface: true
         emit_empty_slices: true
         emit_pointers_for_null_types: true
   ```

4. **Generate sqlc code:**
   ```bash
   make sqlc
   ```
   This creates `db.go`, `models.go`, and `queries.sql.go` in the domain folder.

5. **Create domain files:**
   - `dto.go` - Request/Response models
   - `errors.go` - Domain-specific errors
   - `repository.go` - Data access (uses generated sqlc code)
   - `service.go` - Business logic
   - `handler.go` - HTTP handlers

6. **Register routes** in `internal/router/router.go`

See `internal/user/` for a complete example.

### Adding Database Queries

SQL queries live in each domain's `sql/` subdirectory:

1. Edit `internal/{domain}/sql/queries.sql`
2. Run `make sqlc` to regenerate code
3. Import and use: `import "{yourmodule}/internal/{domain}/sql"`
4. Use generated methods in your repository: `queries *sql.Queries`
